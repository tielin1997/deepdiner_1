# 餐厅系统 (Restaurant System)

> **Status**: Designed (pending review)
> **Author**: zhangtielin + agents
> **Last Updated**: 2026-04-17
> **Implements Pillar**: 高易用性, 动态资源管理, 涌现式策略

## Overview

餐厅系统是《深渊食堂》的**空间画布与基础设施层**。它定义了餐厅的座位布局（每个座位具备独立的特性/Buff）、设施槽位（玩家可通过奖券购买的永久增益载体），以及餐厅的整体空间状态。从数据角度，它是食客分配、卡牌出牌、回合结算等所有空间交互的锚点；从玩家体验角度，它是每局经营活动的"舞台"——玩家看到的是一张张坐满怪物的餐桌和散布其中的设施，感受到的是"我的食堂越来越强"的成长节奏。

餐厅系统的核心职责包括：
1. **座位管理**：维护 N 个座位的状态（空/已占用），每个座位可携带独立的特性修饰符
2. **设施系统**：定义可购买的设施类型及其作用范围（单座位/区域/全局），管理设施的放置与移除
3. **空间状态**：提供查询接口，让其他系统（食客分配、结算、UI）高效获取座位信息和设施效果

## Player Fantasy

**核心幻想：** "我是深渊蛛网的编织者——在每天上涨的营业额压迫下，我必须绞尽脑汁搜刮每个食客的金币，并甄别出那些'美味'的客人将他们变成食材。升级餐桌、更换椅子、购置设施、购买遗物——一切都是布下陷阱，等待食客落入我的蛛网。"

玩家感受到的不是"我在经营一家餐厅"，而是"我在编织一张越来越精密的掠夺之网"。每日上涨的营业额目标是无情的鞭子，逼着玩家不择手段地从食客身上榨取每一枚金币。升级餐桌不是改善体验，是提高猎物的消费上限；放一个保鲜柜不是保鲜食材，是让致命的加菜卡多挥舞一次；每个座位的特性不是装饰，是捕猎的地形优势。

当玩家发现角落座位的"金币-1"debuff 实际上降低了食客的支付能力，配合加菜策略能精准将消费推过食客的承受上限——那个"最差的座位"变成了最高效的**绞肉角**。设施不再是升级，而是**陷阱的升级**。

**a-ha moment：** 玩家意识到"我一直在建造的不是餐厅，而是一台精密的深渊收割机"——每张桌子、每把椅子、每件设施都是齿轮，而每天涌入的食客是被齿轮碾碎的燃料。

## Detailed Design

### Core Rules

**规则 1：座位是可替换的设施**

1. 餐厅初始拥有 4 个座位（基础木椅，无修饰符）
2. 玩家可在商店阶段购买新座位类型，替换现有座位
3. 替换在商店阶段即时完成，**次日营业阶段生效**
4. 替换时旧座位销毁，不退回奖券
5. 座位可通过商店购买新增，最多扩展至 8 个座位

**规则 2：座位具有固定基础特性**

每种座位类型拥有 1-2 个特性修饰符，不可在游戏中更改（只能替换整个座位）。

| ID | 座位类型 | 定位 | 主效果 | 副效果 |
|----|---------|------|--------|--------|
| S1 | 木椅 (Wooden Chair) | 基础 | 无 | 无 |
| S2 | 铁板桌 (Iron Table) | 稳定收入 | 基础餐费 +50% | 加菜餐费 -20% |
| S3 | 绞肉角 (Grinder Corner) | 吞噬型 | 每次加菜 15% 几率直接触发吞噬（无视食客剩余金币） | 所有餐费 -50% |
| S4 | 板前座 (Counter Seat) | 加菜流 | 加菜餐费 +50% | 基础餐费 -100%（食客不产生自动消费） |
| S5 | 贵宾包厢 (VIP Box) | 高风险高回报 | 加菜餐费 +100%，基础餐费 +100%，食客金币 ×500% | 每次加菜 10% 概率引发"霸王餐"（食客支付 0 金币离场） |

**座位策略说明**：

- **木椅**：纯基础选择，无额外效果也无风险
- **铁板桌**：适合"稳扎稳打"策略，高额基础餐费保证每日底线收入，但加菜收益打折
- **绞肉角**：适合"吞噬流"策略，放弃稳定收入换取高频吞噬——每次加菜都是一次赌博，15% 概率直接吞噬无视金币；但所有餐费减半意味着不吞噬就亏大
- **板前座**：适合"精打细算"策略，完全依赖加菜获取收入（基础餐费归零），但加菜收益提高 50%
- **贵宾包厢**：适合"高风险高回报"策略，食客带来巨量金币和翻倍收益，但霸王餐风险随时可能让一切归零

**规则 3：全局设施拥有有限槽位**

1. 全局设施影响所有座位（除非座位有特殊限制）
2. 全局设施槽位上限为 3 个
3. 替换旧设施时旧设施销毁，不退回奖券
4. 全局设施效果与座位特性按叠加顺序计算

**规则 4：修饰符体系**

修饰符分为两级：

**座位级修饰符**（影响单个座位上的食客/卡牌交互）：

| 修饰维度 | 作用对象 | 效果描述 |
|----------|---------|---------|
| 食客金币修饰 | 落座食客 | 增减食客携带金币（百分比） |
| 基础餐费修饰 | 自动餐费 | 增减食客自动产生的消费额（百分比） |
| 加菜餐费修饰 | 加菜卡牌 | 增减打出食材卡的消费附加额（百分比） |
| 吞噬触发几率 | 加菜结算 | 每次加菜时 X% 概率直接触发吞噬 |
| 霸王餐触发几率 | 加菜结算 | 每次加菜时 X% 概率食客支付 0 离场 |
| 耐久度修饰 | 食材卡牌 | 增减该座位上打出卡牌的耐久度消耗 |
| 食客美味度/新鲜度修饰 | 落座食客 | 修改食客的美味度和新鲜度属性 |
| 概率揭示食客属性 | 落座食客 | X% 概率揭示该座位食客的隐藏属性 |

**全局级修饰符**（影响整体营业流程）：

| 修饰维度 | 作用对象 | 效果描述 |
|----------|---------|---------|
| 轮次数量增减 | 每日营业 | 改变当天营业轮次数 |
| 随机产生食材卡 | 牌库 | 每轮次开始时 X% 概率生成一张随机食材卡 |
| 卡牌耐久归零后回收 | 牌库 | 卡牌耐久度归零时 X% 概率回收至手牌 |
| 商店陈列数量 | 商店 | 增减商店每日陈列的设施/遗物数量 |
| 商店打折 | 商店 | 降低商店所有商品价格 X% |
| 每轮加菜出牌上限 | 玩家操作 | 增减每轮次可打出的加菜卡牌数量上限 |
| 种族/食材加菜价格加成 | 特定卡牌 | 提高某一种族或某类食材的加菜餐费 |

**规则 5：修饰符叠加顺序**

当多个来源对同一属性产生修饰时，按以下顺序计算：

```
基础值 → 座位特性修饰（百分比乘算）→ 全局设施修饰（百分比乘算）→ 遗物效果（加法→乘法）→ 事件/Boss 修正
```

1. 百分比修饰按来源层依次乘算（而非加法叠加）
2. 概率类修饰（吞噬几率、霸王餐几率）为加法叠加
3. 最终数值向下取整，最小值不低于 0

**规则 6：座位扩展节奏**

座位扩展由商店系统控制，玩家在商店阶段购买"新座位"即可扩展。初始 4 座位，最大 8 座位。新增座位默认为木椅类型，可后续替换。

### States and Transitions

**座位状态机**：

| 状态 | 描述 | 可转换至 | 触发条件 |
|------|------|---------|---------|
| 锁定 (Locked) | 未解锁的座位槽位 | 空置 | 商店购买新座位 |
| 空置 (Empty) | 无食客的可用座位 | 被占用 | 食客分配系统分配食客到该座位 |
| 被占用 (Occupied) | 有食客正在进食 | 空置 | 轮次结算完成（食客付钱离场或被吞噬） |

状态流转：`[Locked] →(商店购买)→ [Empty] →(食客分配)→ [Occupied] →(结算完成)→ [Empty]`

**餐厅日阶段时序**：

```
日开始
  → 加载当日座位布局和设施效果
  → [轮次循环，最多4轮]
    → 轮次开始：机械手分配食客到空座位（应用座位特性 + 全局设施修饰）
    → 玩家操作阶段：观察面板、加菜出牌
    → 轮次结算：逐食客结算（付钱/吞噬/霸王餐）
  → [轮次循环结束]
  → 日结算：检查营业额目标
  → 商店阶段：购买/替换座位、购买全局设施/遗物
  → 日结束，进入下一天
```

### Interactions with Other Systems

| 交互方向 | 对方系统 | 数据流向 | 接口 |
|----------|---------|---------|------|
| 餐厅 → 食客系统 | 食客系统 | 提供空座位列表 + 座位特性修饰符 | `GetEmptySeats()`, `GetSeatModifier(seatIndex)` |
| 食客系统 → 餐厅 | 食客系统 | 食客落座/离场更新座位状态 | `OccupySeat(seatIndex, dinerId)`, `ReleaseSeat(seatIndex)` |
| 回合流程 → 餐厅 | 回合流程 | 重置所有座位为空置状态 | `ResetAllSeats()` |
| 结算 → 餐厅 | 回合流程/经济 | 查询座位的最终修饰值 | `GetEffectiveModifier(seatIndex, statType)` |
| 商店 → 餐厅 | 经济系统 | 购买/替换座位、购买/替换全局设施 | `TryReplaceSeat()`, `TryAddFacility()`, `TryExpandSeat()` |
| 遗物 → 餐厅 | 遗物系统 | 遗物通过修饰符体系影响餐厅属性 | `GetGlobalFacilityEffects()` |
| UI → 餐厅 | UI 系统 | 渲染座位布局、设施列表、座位特性面板 | `GetActiveSeats()`, `GetFacilitySlots()` |

## Formulas

> **数值说明**：以下公式中所有具体数值（乘数、概率、基础值）均由 Luban 配置表定义，公式仅定义计算结构和合法性约束。数值平衡由专项策划负责。

### F1：有效基础餐费 (Effective Base Fee)

```
EffectiveBaseFee = floor(DinerBaseFee × CookingLevelMultiplier × SeatBaseFeeMod × FacilityBaseFeeMod × RelicBaseFeeMod)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 食客基础餐费 | DinerBaseFee | int | ≥ 0 | 食客自带属性（由食客系统定义） |
| 料理等级乘数 | CookingLevelMultiplier | float | ≥ 0 | 局外升级的料理等级加成（Luban 配置） |
| 座位基础餐费修饰 | SeatBaseFeeMod | float | ≥ 0 | 座位特性对基础餐费的百分比乘算 |
| 全局设施基础餐费修饰 | FacilityBaseFeeMod | float | ≥ 0 | 全局设施对基础餐费的百分比乘算 |
| 遗物基础餐费修饰 | RelicBaseFeeMod | float | ≥ 0 | 遗物对基础餐费的百分比乘算 |

**输出范围：** ≥ 0；板前座（×0.0）输出为 0
**示例：** DinerBaseFee=8, CookingLevel=1.0, 铁板桌(×1.5), 无设施无遗物 → `floor(8 × 1.0 × 1.5 × 1.0 × 1.0) = 12`

### F2：有效加菜餐费 (Effective Add-on Fee)

```
EffectiveAddOnFee = floor(CardFaceValue × SeatAddOnMod × FacilityAddOnMod × RelicAddOnMod)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 卡牌面值 | CardFaceValue | int | ≥ 0 | 食材卡的消费附加额（由卡牌系统定义） |
| 座位加菜餐费修饰 | SeatAddOnMod | float | ≥ 0 | 座位特性对加菜餐费的百分比乘算 |
| 全局设施加菜餐费修饰 | FacilityAddOnMod | float | ≥ 0 | 全局设施对加菜餐费的百分比乘算 |
| 遗物加菜餐费修饰 | RelicAddOnMod | float | ≥ 0 | 遗物对加菜餐费的百分比乘算 |

**输出范围：** ≥ 0
**示例：** CardFaceValue=30, 板前座(×1.5), 无设施无遗物 → `floor(30 × 1.5 × 1.0 × 1.0) = 45`

### F3：有效食客金币 (Effective Diner Gold)

```
EffectiveDinerGold = floor(DinerBaseGold × SeatGoldMod × FacilityGoldMod × RelicGoldMod)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 食客基础金币 | DinerBaseGold | int | ≥ 0 | 食客自带金币（由食客系统定义） |
| 座位金币修饰 | SeatGoldMod | float | ≥ 0 | 座位特性对金币的百分比乘算 |
| 全局设施金币修饰 | FacilityGoldMod | float | ≥ 0 | 全局设施对金币的百分比乘算 |
| 遗物金币修饰 | RelicGoldMod | float | ≥ 0 | 遗物对金币的百分比乘算 |

**输出范围：** ≥ 0
**示例：** DinerBaseGold=140, 贵宾包厢(×5.0), 无设施无遗物 → `floor(140 × 5.0 × 1.0 × 1.0) = 700`

### F4：吞噬触发概率 (Devour Trigger Chance)

```
DevourChance = clamp(SeatDevourChance + FacilityDevourChance + RelicDevourChance, 0.0, 1.0)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 座位吞噬几率 | SeatDevourChance | float | [0.0, 1.0] | 座位特性提供的吞噬概率 |
| 全局设施吞噬几率 | FacilityDevourChance | float | [0.0, 1.0] | 全局设施提供的吞噬概率 |
| 遗物吞噬几率 | RelicDevourChance | float | [0.0, 1.0] | 遗物提供的吞噬概率 |

**输出范围：** [0.0, 1.0]（加法叠加，clamp 至 1.0）
**示例：** 绞肉角(0.15) + 遗物吞噬+5%(0.05) → `clamp(0.15 + 0.05, 0, 1) = 0.20 (20%)`

> 此吞噬触发是**独立判定**，与"总消费 > 食客金币"的判定机制是两个独立的吞噬途径。

### F5：霸王餐触发概率 (Dine-and-Dash Chance)

```
DineAndDashChance = clamp(SeatDineAndDashChance + FacilityDineAndDashChance + RelicDineAndDashChance, 0.0, 1.0)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 座位霸王餐几率 | SeatDineAndDashChance | float | [0.0, 1.0] | 座位特性提供的霸王餐概率 |
| 全局设施霸王餐几率 | FacilityDineAndDashChance | float | [0.0, 1.0] | 全局设施提供的霸王餐概率 |
| 遗物霸王餐几率 | RelicDineAndDashChance | float | [0.0, 1.0] | 遗物提供的霸王餐概率 |

**输出范围：** [0.0, 1.0]（加法叠加）
**示例：** 贵宾包厢(0.10) + 无遗物 → `0.10 (10%)`

### F6：食客总消费 (Total Diner Cost)

```
TotalCost = EffectiveBaseFee + Σ(EffectiveAddOnFee_i)   (i = 1..N)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 有效基础餐费 | EffectiveBaseFee | int | ≥ 0 | 公式 F1 的输出 |
| 第 i 次加菜的有效餐费 | EffectiveAddOnFee_i | int | ≥ 0 | 公式 F2 的输出 |
| 加菜次数 | N | int | ≥ 0 | 该食客被加菜的总次数 |

**输出范围：** ≥ 0
**示例：** 铁板桌，EffectiveBaseFee=12，加菜2次(EffectiveAddOn=8, 16) → `12 + 8 + 16 = 36`

### F7：吞噬判定 (Devour Verdict)

```
DevourVerdict =
  if Random() < DevourChance → DEVOUR_TRIGGERED       // 公式 F4 的独立判定
  else if TotalCost > EffectiveDinerGold → DEVOUR_BY_COST
  else → PAY_SUCCESS
```

**判定优先级**：
1. 先判定吞噬触发概率（公式 F4）—— 每次加菜时独立判定
2. 未触发独立吞噬时，轮次结算时判定总消费 vs 有效金币
3. 两者独立：即使总消费 ≤ 金币，吞噬触发概率仍可生效

**输出：** `DEVOUR_TRIGGERED` | `DEVOUR_BY_COST` | `PAY_SUCCESS`

### F8：日营业额目标 (Daily Revenue Target)

```
DailyTarget = BaseTarget + TargetGrowth × (DayNumber - 1)
```

**变量：**

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础目标 | BaseTarget | int | > 0 | 第 1 天的营业额目标（Luban 配置） |
| 每日增长 | TargetGrowth | int | ≥ 0 | 每天增加的目标额（Luban 配置） |
| 天数 | DayNumber | int | ≥ 1 | 当前天数 |

**输出范围：** > 0
**示例：** BaseTarget=150, TargetGrowth=60, Day 5 → `150 + 60 × 4 = 390`

## Edge Cases

### EC-1：乘法修饰链导致结果为 0

- **If** 座位 = S4 板前座 (SeatBaseFeeMod = 0.0) **与** 任意全局设施/遗物修饰：EffectiveBaseFee = 0，永久为 0。这是 S4 的设计意图（放弃基础收入换加菜加成），不应被后续修饰符修复。
- **If** 低面值卡牌 + 多层折扣叠加导致 floor 后为 0：允许为 0，玩家应避免此组合。
- **If** 食客基础金币 = 0（特殊食客/Boss）：EffectiveDinerGold = 0，任何消费都触发吞噬。金币为 0 的食客定义由食客系统负责。

### EC-2：概率冲突

- **If** 霸王餐与吞噬概率在同一次加菜中同时命中：**霸王餐优先**。食客支付 0 离场，吞噬判定不执行。理由：跑掉的人不能被吃，且霸王餐是更差的结果，符合高风险座位的设计意图。
- **If** 吞噬概率叠加超过 100%：clamp 至 100%，每次加菜必定吞噬。允许 100% 吞噬流作为合法 build。

### EC-3：座位替换时机

- **If** 座位状态为 Occupied 时尝试替换：拒绝替换，返回错误提示。只有 Empty 状态可替换。
- **If** Locked 座位尝试替换（而非扩展）：拒绝。Locked 座位需先通过扩展购买解锁，变为 Empty 后才可替换。
- **If** 座位数已达上限 8 时尝试扩展：`TryExpandSeat()` 返回 false，UI 隐藏或禁用扩展选项。

### EC-4：设施槽位边界

- **If** 3 个槽位全满时购买新设施：玩家必须选择一个已有设施进行替换（销毁旧设施），一步完成购买+替换。
- **If** 设施效果恰好抵消座位负面效果（如设施 ×1.25 抵消 S2 的 ×0.8）：合法游戏状态，乘法链自然计算，无需特殊处理。

### EC-5：板前座 (S4) 特殊场景

- **If** S4 + 玩家不打出任何加菜卡：TotalCost = 0，食客支付 0 离场（PAY_SUCCESS），玩家获得 0 收入。这是 S4 的核心风险——不加菜就白来。
- **If** S4 + 食客金币 = 0：TotalCost = 0 ≤ EffectiveDinerGold = 0 → PAY_SUCCESS，0 收入。双零场景下食客免费离开。

### EC-6：贵宾包厢 (S5) 特殊场景

- **If** S5 霸王餐在第 1 次加菜时触发：食客立即离场，**全部费用（含基础餐费）清零**，玩家获得 0 金币。
- **If** S5 霸王餐在第 N 次加菜时触发：已累积的所有费用（基础 + 前 N 次加菜）全部作废，食客离场。
- **If** S5 + 高金币食客被吞噬：可能获得巨额金币，单次吞噬可能直接完成日目标。这是 S5 的设计意图——高风险高回报。

### EC-7：修饰符约束

- **If** 全局设施/遗物提供 0 值修饰符：设计约束——全局设施和遗物的修饰值范围 ≥ 0.1（仅允许座位特性使用 0.0 作为特殊设计）。
- **If** 负数修饰符被引入：不允许。所有修饰符 ≥ 0，减法效果通过乘以小于 1 的正小数实现。

### EC-8：日营业额边界

- **If** 单轮次收入已超过日目标：该轮次结算后触发提前结束，跳过剩余轮次，进入商店阶段。
- **If** 当日收入为 0（全部霸王餐或零消费）：日目标未达成，但需等 4 轮全部结束才判定失败。
- **If** 日营业额恰好等于目标值：达成（≥ 判定），触发提前结束。

## Acceptance Criteria

1. **GIVEN** 餐厅初始化完成，**WHEN** 查询座位列表，**THEN** 返回 4 个木椅类型的 Empty 状态座位
2. **GIVEN** 4 个空座位，**WHEN** 食客系统请求空座位列表，**THEN** 返回全部 4 个座位
3. **GIVEN** 座位为 Empty，**WHEN** 调用 OccupySeat(0, dinerId)，**THEN** 座位 0 状态变为 Occupied，OccupiedByDinerId = dinerId
4. **GIVEN** 座位为 Occupied，**WHEN** 调用 ReleaseSeat(0)，**THEN** 座位 0 状态变为 Empty，OccupiedByDinerId = 0
5. **GIVEN** 座位类型 = S2 铁板桌，**WHEN** 计算 EffectiveBaseFee(DinerBaseFee=10)，**THEN** 结果 = 15（10 × 1.5）
6. **GIVEN** 座位类型 = S4 板前座，**WHEN** 计算 EffectiveBaseFee(DinerBaseFee=10)，**THEN** 结果 = 0（10 × 0.0）
7. **GIVEN** 座位类型 = S5 贵宾包厢，**WHEN** 计算 EffectiveDinerGold(DinerBaseGold=100)，**THEN** 结果 = 500（100 × 5.0）
8. **GIVEN** 3 个全局设施槽位已满，**WHEN** 调用 TryAddFacility()，**THEN** 返回 false 或要求指定替换目标
9. **GIVEN** 座位数 = 8（上限），**WHEN** 调用 TryExpandSeat()，**THEN** 返回 false
10. **GIVEN** 座位类型 = S3 绞肉角，**WHEN** 加菜结算，**THEN** 15% 概率触发吞噬（DevourChance = 0.15）
11. **GIVEN** 座位类型 = S5 贵宾包厢，**WHEN** 霸王餐触发，**THEN** 食客立即离场，全部费用（含基础餐费）清零
12. **GIVEN** 霸王餐与吞噬同时命中，**WHEN** 判定优先级，**THEN** 霸王餐优先，吞噬判定不执行
13. **GIVEN** 修饰符叠加链（座位 + 全局设施 + 遗物），**WHEN** 计算最终值，**THEN** 按乘法链顺序计算，结果 ≥ 0
14. **GIVEN** Day 5，**WHEN** 查询日营业额目标，**THEN** 返回 390（150 + 60 × 4）
