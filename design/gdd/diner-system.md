# 食客系统 (Diner System)

> **Status**: In Design
> **Author**: zhangtielin + agents
> **Last Updated**: 2026-04-17
> **Implements Pillar**: 高易用性, 动态资源管理, 涌现式策略

## Overview

食客系统是《深渊食堂》的**核心交互对象和策略引擎**。从数据角度，它定义了食客的完整属性体系（金币、美味度、新鲜度、种族、情绪路径）、生成规则（每轮次从食客池随机抽取并分配到餐厅座位）、以及食客从"被分配"到"离场/被吞噬"的完整生命周期状态机。从玩家角度，食客是每轮次策略决策的焦点——玩家通过观察食客的视觉外观推断美味度与新鲜度，通过情绪反馈的变化判断金币余量，决定是稳妥收取基础餐费还是冒险加菜追求更高收益或触发吞噬。

食客系统的核心职责包括：

1. **食客属性定义**：维护食客的金币（隐藏属性）、美味度、新鲜度、种族等核心数据
2. **随机生成与分配**：从种族/属性加权的食客池中生成食客，通过餐厅系统的空座位接口分配落座
3. **情绪反馈系统**：管理食客的情绪路径（情绪在加菜过程中按路径规则演化），为玩家提供非精确的金币推断线索
4. **食客生命周期**：管理食客从生成到离场（付费离开或被吞噬）的完整状态流转
5. **吞噬输出接口**：提供食客被吞噬时卡牌系统所需的数据（种族、美味度、新鲜度）

## Player Fantasy

**核心幻想：** "我是深渊猎人，食客是我的猎物。我看不见它们身上挂着的价签，但我能从每一次情绪波动里读出破绽——轻松的微笑是铠甲，突变的惶恐是伤口，虚假的镇定是陷阱。我的每一张加菜卡都是一次试探性的收线：再近一步，我能撕开它的伪装；再多收一次，它可能从我手里滑走。"

**情感锚点：** 每一次加菜都是猎人向猎物逼近一步——猎物会挣扎、会伪装、会突然暴起。玩家的每一次加菜决策都是在信息不完全的情况下赌上自己的卡牌资源（耐久度），试图在猎物脱钩之前精确地把它推过金币上限。这既不是蛮力碾压，也不是纯靠运气——是**读心**。

**关键玩家时刻：**

1. **猎物入场（落座）**：机械手将食客甩到座位上。猎人的第一眼扫过猎物全貌——形象的精致程度（美味度）和鲜活程度（新鲜度）暗示了这头猎物的"营养价值"。但它口袋里的金币是个黑洞，猎人只能从落座时的第一个表情里嗅出一丝线索：轻松、焦虑、还是镇定？这就像浮漂的第一下颤动——有东西上钩了，但还不知道是什么。

2. **步步逼近（加菜试探）**：每打出一张加菜卡就是向猎物逼近一步、把钓线收紧一分。猎物的情绪反应就是它的"恐惧气味"——但恐惧有很多种味道。豪爽型猎物大摇大摆，也许是个肥美的大家伙，也许只是虚张声势的小角色。紧张型猎物每次都发抖，可能只是天生胆小。伪装型猎物前几步镇定自若，突然在第三步暴露出真实的恐惧——"原来你一直在装"。猎人的每一次抉择都在衡量：收线再紧一点，是捕获还是断线？

3. **一击致命（精准吞噬）**：最极致的猎人体验不是疯狂加菜，而是在恰到好处的时机收手——刚好把消费推过食客的金币线，一击必杀。多加一次菜浪费一张卡的耐久度，少加一次让猎物逃走。那个"刚刚好"的时刻，就是猎人的巅峰体验。

4. **猎物反噬（意外风险）**：贵宾包厢的霸王餐让一切归零，绞肉角的随机吞噬可能过早打断一次精心策划的狩猎。猎人不是永远安全——每一次逼近都伴随着被猎物反噬的风险。

**a-ha moment：** 玩家经历一轮"完美狩猎"——对一个食客加菜恰好三次，第三次时食客情绪突然从镇定变为恐惧（伪装型路径的临界点），玩家果断结束轮次，结算时消费刚好超出金币 2 点。精确到 2 点的差距——不是蛮力，是读心术。从此玩家不再只看当前情绪，而是试图预测情绪路径的拐点："我不是在加菜，我是在拆解猎物的心理防线。"

## Detailed Design

### Core Rules

**规则 1：食客属性体系**

每个食客实例拥有以下核心属性：

| 属性 | 类型 | 可见性 | 描述 |
|------|------|--------|------|
| DinerId | int | 系统 | 唯一标识 |
| RaceId | int | 系统 | 种族 ID |
| DinerBaseGold | int | **隐藏** | 食客携带的基础金币（由食客模板 + 情绪路径偏移共同决定） |
| DinerBaseFee | int | **隐藏** | 食客产生的基础餐费（由食客模板决定） |
| Flavor | int | **视觉映射** | 美味度（映射到视觉外观的精致程度；吞噬时决定产出食材卡面值） |
| Freshness | int | **视觉映射** | 新鲜度（映射到视觉外观的鲜活程度；吞噬时决定产出食材卡初始耐久度） |
| EmotionPathId | int | 系统 | 分配的情绪路径 ID |
| CurrentEmotion | enum | **公开** | 当前情绪表情（MVP 阶段用 emoji 表示） |
| Traits | string[] | 系统 | 食客特性标签（吞噬产出加成、特殊行为等） |
| GoldSpentRatio | float | 系统 | 已消费金额占有效金币的比例（情绪判定用） |

**属性可见性规则**：

- **隐藏**属性：玩家无法看到精确数值，只能通过间接手段推断
- **视觉映射**属性：通过食客的视觉外观表现（不显示数字），玩家通过"看脸"获得信息
- **公开**属性：直接可见的情绪表情（MVP 阶段用 emoji）
- 系统属性：仅供内部逻辑使用

**规则 2：种族系统（6 种基础种族）**

种族定义食客的视觉种族类型和背景设定，种族的属性范围（金币、美味度、新鲜度、基础餐费）**全部由 Luban TbDinerTemplate 表配置**，GDD 不硬编码具体数值。

MVP 阶段包含 6 种基础种族：

| ID | 种族名 | 设计定位 | 视觉特征方向 |
|----|--------|---------|------------|
| R1 | 史莱姆 (Slime) | 入门级 | 圆润、半透明、多色彩变体 |
| R2 | 哥布林 (Goblin) | 常见型 | 矮小精悍、表情丰富 |
| R3 | 深海族 (Abyssal) | 珍稀型 | 触手、深海生物特征 |
| R4 | 蘑菇族 (Mushroom) | 策略型 | 菌帽体型、孢子特效 |
| R5 | 骷髅族 (Skeleton) | 高风险型 | 骨骼外露、暗色调 |
| R6 | 幽灵族 (Ghost) | 特殊型 | 半透明漂浮、闪烁 |

**种族设计原则**：

- 种族决定视觉外观和背景设定
- 属性范围由 TbDinerTemplate 中每种族的模板实例配置
- 每个种族的模板实例确保至少有一个"签名属性"明显区别于其他种族
- 吞噬产出特性**不与种族绑定**，作为独立的食客特性（Traits）设计

**规则 3：食客特性系统（Traits）**

食客特性是与种族独立的附加属性，分为三大类别：

**A. 吞噬相关特性**

| 特性 ID | 特性名 | 效果 | 描述 |
|---------|--------|------|------|
| T-D1 | 坚韧之躯 | 抵御吞噬 N 次 | 该食客可承受 N 次吞噬判定而不被吞噬；第 N+1 次吞噬判定才生效 |
| T-D2 | 连坐诅咒 | 吞噬时随机选择 1 个其他在场食客同时吞噬 | 当此食客被吞噬时，随机选一个其他 Occupied 座位的食客一同进入吞噬流程 |
| T-D3 | 富脂收益 | 吞噬时额外获得基础餐费的 X% | 吞噬结算时，额外收入 = EffectiveBaseFee × X% |
| T-D4 | 奢华回报 | 吞噬时额外获得加菜餐费总额的 X% | 吞噬结算时，额外收入 = Σ(EffectiveAddOnFee) × X% |
| T-D5 | 幽灵残留 | 吞噬时有 X% 概率产出额外一张食材卡 | 原概率产 1 张，X% 概率额外产 1 张同种族食材卡 |

**B. 加菜相关特性**

| 特性 ID | 特性名 | 效果 | 描述 |
|---------|--------|------|------|
| T-A1 | 挑食体质 | 抵御加菜 N 次 | 前 N 次对食客的加菜尝试无效（加菜餐费为 0，不消耗卡牌耐久度） |
| T-A2 | 打赏习惯 | 被加菜时给予小费 | 每次被加菜时，额外支付 DinerBaseFee × X% 作为小费加入营业额 |
| T-A3 | 爆金体质 | 被加菜时所有其他食客损失金币 | 每次加菜时，所有其他在场食客金币 -Y%（乘算减少） |
| T-A4 | 霸道气场 | 被加菜时降低所有其他食客属性 | 每次加菜时，所有其他食客美味度/新鲜度 -1 |

**C. 属性与环境影响特性**

| 特性 ID | 特性名 | 效果 | 描述 |
|---------|--------|------|------|
| T-E1 | 免费试吃 | 抵御基础餐费 | 食客不产生基础餐费（EffectiveBaseFee = 0），类似板前座效果 |
| T-E2 | 气味外溢 | 影响相邻座位食客金币 +X% | 落座后，相邻座位（左右）的食客金币乘以 (1 + X%) |
| T-E3 | 压迫感 | 影响相邻座位食客基础餐费 -Y% | 落座后，相邻座位的食客基础餐费乘以 (1 - Y%) |
| T-E4 | 霸占食欲 | 影响相邻座位加菜餐费 +Z% | 落座后，相邻座位的加菜餐费乘以 (1 + Z%) |

**特性系统规则**：

1. 食客可拥有 0-2 个特性（由 TbDinerTemplate 配置）
2. 同类特性（同为吞噬类/加菜类/环境类）可叠加
3. 特性在食客实例化时确定，整局不变
4. Boss 食客可拥有专属特性（如"法术护盾"抵御吞噬 3 次）
5. 特性的具体数值（N 次、X%、Y%）全部由 TbDinerTemplate 配置

**规则 4：每日食客池（Luban 表链驱动）**

食客生成通过三级 Luban 配置表链控制：

```
关卡表 (TbStage) → 食客池表 (TbDinerPool) → 食客模板表 (TbDinerTemplate)
```

- **TbDinerTemplate**：定义食客模板（种族 ID、金币范围、美味度范围、新鲜度范围、基础餐费、情绪路径权重、特性列表）
- **TbDinerPool**：定义每日食客池（引用 TbDinerTemplate 的模板 + 数量权重）
- **TbStage**：定义关卡配置（天数、引用哪个食客池、营业额目标等）

**每日食客池生成规则**：

1. 日开始时，根据 `DayNumber` 从 TbStage 查询当日关卡配置
2. 从 TbDinerPool 获取当日食客池定义
3. 按配置的权重和数量实例化食客列表
4. 列表随机打乱顺序，形成当日食客队列

**池抽取规则（有放回）**：

1. 每轮次开始时，从食客队列中抽取食客填充空座位
2. **允许重复抽取**：同一模板可产生多个实例，同一食客可在不同轮次出现
3. 抽取数量 = min(队列剩余数, 空座位数)
4. 若队列耗尽但仍有空座位，剩余座位保持空置

**规则 5：情绪路径系统（Luban 配置驱动）**

情绪路径的全部参数由 Luban TbEmotionPath 表配置：

- **路径定义**：每种路径包含名称、金币分布偏移系数、情绪步骤列表
- **情绪步骤**：每个步骤包含消费比例阈值和对应情绪类型
- **情绪类型枚举**：轻松(E1) / 紧张(E2) / 惶恐(E3) / 恐惧(E4)
- **初始情绪**：由路径的第一个步骤决定
- **MVP 表现**：情绪用 emoji 风格呈现

MVP 阶段包含 4 种情绪路径：

| 路径 | 金币分布偏移 | 签名行为 | 策略含义 |
|------|------------|---------|---------|
| 豪爽型 | 金币 ×1.2 | 全程轻松，最后阶段突变 | 多数确实有钱，少数"装阔" |
| 紧张型 | 金币 ×0.9 | 每次加菜都紧张 | 多数实际不穷，只是胆小 |
| 伪装型 | 金币方差 ×2.0 | 前期镇定，中期突变 | 两极分化——很富或很穷 |
| 平稳型 | 金币 ×1.0 | 情绪均匀递增 | 可预测，新手基准 |

**情绪变化规则**：

1. 食客落座时展示初始情绪
2. 每次加菜后，更新 `GoldSpentRatio`（已消费金额 / 有效金币），查 TbEmotionPath 获取新情绪
3. 情绪步骤的阈值-情绪映射**不要求单调递增**（伪装型可从"轻松"直接跳到"恐惧"）
4. 同一种族、同一金币的食客因路径不同展现完全不同的情绪模式
5. 情绪路径在食客实例化时从权重列表中随机分配（由 TbDinerTemplate 配置权重）

**规则 6：食客落座规则**

1. 每轮次开始，食客系统调用餐厅系统 `GetEmptySeats()` 获取空座位列表
2. 从食客队列中抽取食客（数量 = min(队列剩余, 空座位数)）
3. 每个食客随机分配到一个空座位，调用 `OccupySeat(seatIndex, dinerId)`
4. 落座后进入 DineState，产生基础餐费（由餐厅系统 F1 公式计算）
5. 展示初始情绪表情（emoji）
6. 食客的有效金币和餐费由餐厅修饰符链计算（食客系统只提供基础值）

**规则 7：食客加菜交互规则**

1. 玩家对食客打出食材卡时，食客系统执行：
   a. 接收卡牌面值（来自卡牌系统）
   b. 通过餐厅系统获取座位修饰符，计算有效加菜餐费（餐厅系统 F2）
   c. 更新食客累积消费和 `GoldSpentRatio`
   d. 查 TbEmotionPath 获取新情绪，触发情绪变化事件
   e. 餐厅系统执行吞噬/霸王餐概率判定（F4/F5）
   f. 返回结果：情绪变化、吞噬/霸王餐判定结果
2. 食客**不直接管理金币增减**——金币判定在结算阶段统一处理

### States and Transitions

**食客状态机**：

| 状态 | 描述 | 可转换至 | 触发条件 |
|------|------|---------|---------|
| 未生成 (Unspawned) | 存在于每日池但未激活 | 等待分配 | 轮次开始，有空座位 |
| 等待分配 (Pending) | 已抽取，等待分配座位 | 落座 | 随机选择空座位 |
| 落座 (Seated) | 已落座，产生基础餐费 | 进食中 | 基础餐费计算完成，展示初始情绪 |
| 进食中 (Dining) | 等待玩家加菜决策 | 结算中 | 玩家结束轮次或加菜触发吞噬/霸王餐 |
| 结算中 (Settling) | 执行付钱/吞噬/霸王餐判定 | 已离场 / 被吞噬 | 判定完成 |
| 已离场 (Left) | 付费后离开 | — | 终态，释放座位 |
| 被吞噬 (Devoured) | 被绞肉机处理 | — | 终态，释放座位，通知卡牌系统 |

**状态流转**：

```
[Unspawned] →(轮次开始)→ [Pending] →(分配座位)→ [Seated]
  →(基础餐费结算)→ [Dining] →(结束轮次/触发特殊)→ [Settling]
  →(付钱成功)→ [Left]
  →(吞噬判定)→ [Devoured]
```

**特殊转换**：

- Dining 状态中，每次加菜后若触发吞噬/霸王餐概率（餐厅 F4/F5），直接跳转 Settling 并立即结算
- Dining 状态中，食客可被多次加菜（不产生状态转换，仅更新情绪和累积消费）

### Interactions with Other Systems

| 交互方向 | 对方系统 | 数据流向 | 接口 |
|----------|---------|---------|------|
| 食客 → 餐厅 | 餐厅系统 | 查询空座位、落座/释放 | `GetEmptySeats()`, `OccupySeat()`, `ReleaseSeat()` |
| 餐厅 → 食客 | 餐厅系统 | 提供座位修饰符 | `GetSeatModifier(seatIndex, statType)` |
| 食客 → 卡牌 | 卡牌系统 | 吞噬通知（种族、美味度、新鲜度、特性） | `OnDinerDevoured(dinerId, raceId, flavor, freshness, traits[])` |
| 回合流程 → 食客 | 回合流程系统 | 触发生成、触发结算 | `GenerateAndAssignDiners()`, `SettleRound()` |
| 食客 → 回合流程 | 回合流程系统 | 返回结算结果 | `SettleResult` 结构 |
| UI → 食客 | UI 系统 | 查询可见信息和情绪 | `GetVisibleInfo(dinerId)`, `GetCurrentEmotion(dinerId)` |
| 食客 → UI | UI 系统 | 情绪变化事件、吞噬事件 | `OnEmotionChanged`, `OnDinerDevoured` 事件 |

## Formulas

> **设计原则**：食客系统的所有数值（金币范围、美味度、新鲜度、基础餐费、特性参数、情绪步骤等）**全部由 Luban 配置表直接提供**。本节不定义数学公式，仅描述数据来源、计算规则和数据流向。

### FD1：食客属性数据来源

所有食客属性从 Luban 配置表直接读取或随机采样，不经公式计算：

| 属性 | 数据来源 | 生成规则 |
|------|---------|---------|
| DinerBaseGold | TbDinerTemplate.GoldMin/Max × TbEmotionPath.GoldMultiplier | 从配置范围随机取值，乘以路径金币乘数（伪装型额外二次随机：50%×2 / 50%÷2） |
| Flavor | TbDinerTemplate.FlavorMin/Max | 从配置范围随机取值 |
| Freshness | TbDinerTemplate.FreshnessMin/Max | 从配置范围随机取值 |
| DinerBaseFee | TbDinerTemplate.BaseFee | 固定值，直接读取 |
| EmotionPathId | TbDinerTemplate.EmotionPathWeights | 按权重随机选取 |
| Traits | TbDinerTemplate.TraitIds | 直接读取（0-2 个） |

**伪装型二次随机规则**：生成基础金币后，50% 概率乘以 2.0，50% 概率除以 2.0（实现两极分化效果）。

**属性输出说明**：
- `DinerBaseFee` 和 `DinerBaseGold` 作为输入传递给餐厅系统的修饰符链（F1、F3）
- `Flavor` 和 `Freshness` 在吞噬事件时传递给卡牌系统（决定产出食材卡面值和初始耐久度）

### FD2：情绪判定规则

情绪变化不使用公式，完全由 TbEmotionPath 配置表驱动查表：

**输入**：`GoldSpentRatio` = CumulativeSpent ÷ EffectiveDinerGold（简单除法，非公式）

**查表规则**：

1. 从 TbEmotionPath 获取该路径的情绪步骤列表（按 Threshold 升序排列）
2. 找到最大的 `Threshold ≤ GoldSpentRatio` 的步骤
3. 返回该步骤的 EmotionType（E1 轻松 / E2 紧张 / E3 惶恐 / E4 恐惧）
4. 若 GoldSpentRatio < 第一个步骤的 Threshold，返回第一个步骤的情绪（初始情绪）

**示例（伪装型）**：步骤=[{0.0, E1}, {0.5, E4}]，GoldSpentRatio=0.3 → E1；GoldSpentRatio=0.6 → E4

### FD3：食客特性效果规则

所有特性效果数值由 TbDinerTemplate 的特性配置直接提供。以下仅描述特性的**作用规则**（非公式）：

**吞噬类特性**：

| 特性 | 作用规则 | 配置参数 |
|------|---------|---------|
| T-D1 坚韧之躯 | 抵御吞噬 N 次后才真正触发吞噬 | ResistCount (int) |
| T-D2 连坐诅咒 | 吞噬时随机选一个其他 Occupied 座位的食客一同吞噬 | — |
| T-D3 富脂收益 | 吞噬时额外收入 = EffectiveBaseFee × 配置比例 | BonusRatio (float) |
| T-D4 奢华回报 | 吞噬时额外收入 = 累积加菜餐费 × 配置比例 | BonusRatio (float) |
| T-D5 幽灵残留 | 吞噬时按配置概率额外产一张食材卡 | ExtraCardChance (float) |

**加菜类特性**：

| 特性 | 作用规则 | 配置参数 |
|------|---------|---------|
| T-A1 挑食体质 | 前 N 次加菜无效（餐费为 0，不消耗卡牌耐久度） | ResistCount (int) |
| T-A2 打赏习惯 | 每次加菜额外支付小费 = DinerBaseFee × 配置比例 | TipRatio (float) |
| T-A3 爆金体质 | 每次加菜时所有其他食客金币按配置比例减少 | GoldLossRatio (float) |
| T-A4 霸道气场 | 每次加菜时所有其他食客美味度/新鲜度 -配置值 | AttrReduction (int) |

**环境类特性**：

| 特性 | 作用规则 | 配置参数 |
|------|---------|---------|
| T-E1 免费试吃 | EffectiveBaseFee = 0（覆盖餐厅系统计算结果） | — |
| T-E2 气味外溢 | 相邻座位食客金币按配置比例增加 | AdjGoldBonus (float) |
| T-E3 压迫感 | 相邻座位食客基础餐费按配置比例减少 | AdjFeeReduction (float) |
| T-E4 霸占食欲 | 相邻座位加菜餐费按配置比例增加 | AdjAddOnBonus (float) |

### FD4：数据流总览

```
TbDinerTemplate → 生成食客实例（属性采样 + 路径分配 + 特性绑定）
  ↓
食客落座 → 提供 DinerBaseFee, DinerBaseGold 给餐厅系统修饰符链
  ↓
加菜 → 更新 CumulativeSpent → 计算 GoldSpentRatio → 查 TbEmotionPath → 更新情绪
  ↓
结算 → 餐厅系统判定 Pay/Devour/DineAndDash
  ↓
吞噬 → 提供 Flavor, Freshness, RaceId, Traits 给卡牌系统生成食材卡
```

## Edge Cases

### EC-1：伪装型二次随机金币归零

- **If** 伪装型食客的 RawGold = 1，且二次随机命中 ÷2：`floor(1 ÷ 2) = 0`，DinerBaseGold = 0
- **结果**：EffectiveDinerGold = 0，任何消费都触发吞噬
- **理由**：允许金币为 0 的设计意图。TbDinerTemplate 配置需注意低 GoldMin 的伪装型模板可能产出 0 金币食客

### EC-2：T-A3 爆金体质将其他食客金币压至 0

- **If** 多次加菜触发 T-A3，其他食客金币反复乘以 (1 - GoldLossRatio)，经多次 floor 后降至 0
- **结果**：被压至 0 的食客即使只有基础餐费也触发吞噬（TotalCost > 0 > EffectiveDinerGold = 0）
- **理由**：允许金币为 0，T-A3 的"互害"设计是有意为之。配置时需控制 GoldLossRatio 避免一两次加菜就清零

### EC-3：落座即超支（EffectiveDinerGold < EffectiveBaseFee）

- **If** 座位/设施的金币修饰为负向，导致有效金币 < 基础餐费
- **结果**：落座时不判吞噬，等待轮次结算。但 GoldSpentRatio 已经 ≥ 1.0，情绪直接跳到高级别（查表自然处理）
- **理由**：吞噬判定仅在轮次结算和加菜概率触发时执行，不在落座时执行

### EC-4：T-A1 挑食体质抵御期间的加菜

- **If** 食客有 T-A1(ResistCount=2)，前 2 次加菜被抵御
- **结果**：抵御的加菜——餐费为 0、不消耗卡牌耐久度、GoldSpentRatio 不更新、情绪不变
- **理由**：抵御的加菜不算"有效加菜"，玩家无法通过抵御的加菜获取任何信息

### EC-5：T-D2 连坐诅咒不递归

- **If** 食客 A（有 T-D2）被吞噬，连带选中食客 B（也有 T-D2）
- **结果**：B 被吞噬，但 B 的 T-D2 **不再触发连带**。连坐只执行一层
- **理由**：防止链式吞噬导致失控收益。实现时标记"已处理连坐"避免递归

### EC-6：T-D1 坚韧之躯统一计数

- **If** 食客有 T-D1(ResistCount=1)，先被绞肉角概率吞噬命中一次（抵御），后被超支吞噬判定命中
- **结果**：ResistCount 已耗尽（= 0），超支吞噬正常生效。概率吞噬和超支吞噬共享 ResistCount
- **理由**：统一简化模型。"坚韧"抵御所有吞噬来源，不区分触发方式

### EC-7：T-D1 抵御时 T-D2 不触发

- **If** 食客 A（有 T-D1 + T-D2）被吞噬判定命中但被 T-D1 抵御
- **结果**：吞噬未发生，T-D2 连坐不触发。T-D2 只在"吞噬真正发生"时触发
- **理由**：T-D1 是吞噬判定的前置过滤（吞噬未发生），不是事后取消

### EC-8：霸王餐优先于所有吞噬相关特性

- **If** 贵宾包厢霸王餐概率命中，食客有 T-D1/T-D2/T-D3/T-D4/T-D5
- **结果**：霸王餐直接生效，食客支付 0 离场。所有吞噬相关特性不触发
- **理由**：霸王餐优先于吞噬是餐厅系统既定规则。吞噬未发生 → 吞噬特性无触发条件

### EC-9：环境类特性为持续 aura

- **If** 食客 A 有 T-E2（相邻金币 +X%），食客 B 坐在 A 旁边
- **结果**：A 在场期间 B 的金币持续受 T-E2 影响。A 离场/被吞噬后效果立即消失。若 T-A3 减少 B 的金币，T-E2 不会重新加成——aura 作用于当前值，不追溯
- **理由**：aura 模型下 T-E2 的加成在每次查询食客金币时应用

### EC-10：环境 aura 的相邻定义

- **If** 食客 A 有 T-E2，坐在座位 index=0
- **结果**：只影响右侧座位（index=1），不影响左侧（无左邻）。同理 index=7 只影响 index=6
- **理由**：相邻 = 座位 index ± 1。边缘座位只影响一侧

### EC-11：两个 T-A3 爆金体质的互害

- **If** 食客 A 和 B 都有 T-A3。A 被加菜时 B 金币减少，B 被加菜时 A 金币减少
- **结果**：交替加菜导致双方金币螺旋下降，可降至 0
- **理由**：有意的"互害"设计。T-A3 不影响自身（"所有其他在场食客"排除自身）

### EC-12：T-E4 霸占食欲与座位修饰符链

- **If** 食客 A 有 T-E4（相邻加菜餐费 +Z%），食客 B 在相邻座位
- **结果**：T-E4 的加成加入 B 所在座位的 AddOnMod 乘法链（在座位特性之后、全局设施之前）。A 离场时从链中移除
- **理由**：aura 效果融入修饰符乘法链，保持计算一致性

### EC-13：S4 板前座 + T-A2 打赏习惯

- **If** 食客有 T-A2（小费 = DinerBaseFee × TipRatio），坐在板前座 S4（EffectiveBaseFee = 0）
- **结果**：小费 = EffectiveBaseFee × TipRatio = 0 × TipRatio = 0。T-A2 在 S4 上完全无效
- **理由**：T-A2 的计算基础使用 EffectiveBaseFee（经修饰符链后的值），保持一致性

### EC-14：T-E1 免费试吃 + S5 贵宾包厢

- **If** 食客有 T-E1（基础餐费 = 0），坐在 S5（基础餐费 ×2.0）
- **结果**：T-E1 后置覆盖乘法链结果，EffectiveBaseFee = 0
- **理由**：T-E1 是后置覆盖，无论乘法链算出多少都覆盖为 0

### EC-15：T-E1 免费试吃 + 伪装型情绪路径

- **If** 食客有 T-E1（基础餐费 = 0）+ 伪装型路径。落座时 CumulativeSpent = 0
- **结果**：伪装型突变点更难达到（起始消费为 0，只有加菜贡献），玩家需要更多加菜才能看到情绪突变
- **理由**：T-E1 改变了消费累积的起点，使伪装型食客更难被探底——合理的特性交互

### EC-16：食客池不耗尽（有放回抽取）

- **If** 当日食客池配置了固定模板集合和权重，各轮次从中按权重随机抽取
- **结果**：池永远不会耗尽（有放回抽取）。同一模板可在不同轮次出现，但每次是新实例（新 DinerId、重新随机属性值）
- **理由**：有放回抽取 = 无限池。同模板多轮出现是设计意图（增加不确定性）

### EC-17：轮次中食客被吞噬后不补充

- **If** 轮次进行中某食客被吞噬或触发霸王餐，该座位变回 Empty
- **结果**：本轮不会补充新食客到该座位。座位保持 Empty 直到下个轮次开始
- **理由**：食客仅在轮次开始时分配。轮次中吞噬/霸王餐产生的空位不再补充

### EC-18：所有食客被吞噬/霸王餐后轮次未结束

- **If** 加菜过程中所有在场食客都被吞噬或霸王餐，全部座位变 Empty
- **结果**：轮次提前结束（无可操作对象）。回合流程系统应检测"所有座位 Empty"作为轮次结束条件
- **理由**：在回合流程系统 GDD 中定义此判定

### EC-19：S3 绞肉角低面值卡牌加菜为 0

- **If** S3 所有餐费 ×0.5，低面值卡牌 floor(1 × 0.5) = 0
- **结果**：加菜餐费为 0 但仍算一次"加菜行为"。T-A1 的 ResistCount 会消耗。卡牌耐久度照常消耗
- **理由**：加菜行为本身不计餐费多少，行为发生即消耗资源

|------|------|------|---------|----------|

**数据流总览**：

```text
餐厅系统 (座位状态、修饰符)
    ↓

    ↓

    ↓

```

**双向依赖验证**：

- 餐厅系统 GDD 列出"食客系统"为下游依赖 ✅
- 卡牌系统 GDD 尚未设计（需在卡牌 GDD 中列出"食客系统"为上游依赖）
- 回合流程系统 GDD 尚未设计（需在回合流程 GDD 中列出"食客系统"为交互系统）

## Tuning Knobs

所有数值由 Luban 配置表提供，以下列出可调节旋钮及其影响范围：

| 旋钮 | 配置表 | 字段 | 安全范围 | 调高效果 | 调低效果 |
|------|--------|------|---------|---------|---------|
| 种族金币范围 | TbDinerTemplate | GoldMin/Max | ≥ 0 | 食客更富有，吞噬收益更高 | 食客更穷，更容易触发吞噬 |

| 情绪路径金币乘数 | TbEmotionPath | GoldMultiplier | > 0 | 该路径食客金币偏离基准更多 | 更接近基准 |
| 伪装型二次随机倍率 | 常量 | DisguiseMultiplier | > 1.0 | 两极分化更极端 | 分化更温和 |

## Acceptance Criteria

### 属性生成

1. **GIVEN** TbDinerTemplate 配置 RaceId=R1, GoldMin=30, GoldMax=80, FlavorMin=1, FlavorMax=3, FreshnessMin=2, FreshnessMax=4, BaseFee=5, **WHEN** 生成食客实例, **THEN** RaceId=R1, DinerBaseGold ∈ [30,80], Flavor ∈ [1,3], Freshness ∈ [2,4], DinerBaseFee=5

2. **GIVEN** 情绪路径=豪爽型(GoldMultiplier=1.2), 模板 GoldMin=GoldMax=100, **WHEN** 生成金币(固定种子), **THEN** DinerBaseGold=floor(100×1.2)=120

3. **GIVEN** 情绪路径=伪装型, RawGold=100(固定种子), **WHEN** 二次随机命中 ×2.0 分支, **THEN** DinerBaseGold=200；**WHEN** 命中 ÷2.0 分支, **THEN** DinerBaseGold=50

4. **GIVEN** TbDinerTemplate 配置 0 个特性, **WHEN** 生成食客, **THEN** Traits 数组长度=0；**GIVEN** 模板配置 2 个特性, **THEN** Traits 数组长度=2

### 食客池与分配

5. **GIVEN** DayNumber=3, TbStage(Day=3) 指向 TbDinerPool(PoolId=2), **WHEN** 查询食客池, **THEN** 返回 TbDinerPool(PoolId=2) 中的所有模板和权重

6. **GIVEN** 食客池含 1 个模板, **WHEN** 连续 2 轮抽取, **THEN** 2 轮均可成功生成食客实例（有放回，池不耗尽）

7. **GIVEN** 4 个空座位, 食客队列有 4 个食客, **WHEN** 调用分配, **THEN** 4 个食客各分配到一个空座位, 调用 OccupySeat 4 次, 座位状态变为 Occupied

### 情绪系统

8. **GIVEN** 情绪路径步骤=[{0.0,E1}, {0.3,E2}, {0.6,E3}, {0.9,E4}], **WHEN** GoldSpentRatio=0.0, **THEN** 初始情绪=E1(轻松)

9. **GIVEN** 情绪路径步骤同上, **WHEN** GoldSpentRatio=0.5, **THEN** 情绪=E2(紧张)（最大 threshold≤0.5 的步骤）

10. **GIVEN** 伪装型路径步骤=[{0.0,E1}, {0.5,E4}], **WHEN** GoldSpentRatio=0.3, **THEN** 情绪=E1；**WHEN** GoldSpentRatio=0.6, **THEN** 情绪=E4(恐惧，直接跳过 E2/E3)

### 食客状态机

11. **GIVEN** 食客在 Unspawned, **WHEN** 依次触发分配→落座→结算(付费成功), **THEN** 状态序列为 Unspawned→Pending→Seated→Dining→Settling→Left, 座位调用 ReleaseSeat

12. **GIVEN** 食客在 Dining, **WHEN** 结算判定为吞噬, **THEN** 状态序列为 Dining→Settling→Devoured, 通知卡牌系统 OnDinerDevoured(raceId, flavor, freshness, traits)

### 吞噬类特性

13. **GIVEN** 食客有 T-D1(ResistCount=1), **WHEN** 吞噬判定命中第 1 次, **THEN** ResistCount 变为 0, 食客不被吞噬, 状态仍为 Dining

14. **GIVEN** 食客有 T-D1(ResistCount=1), 已抵御 1 次, **WHEN** 再次被吞噬判定命中(概率或超支), **THEN** 吞噬正常生效(统一计数)

15. **GIVEN** 食客 A 有 T-D2, 在场食客 B(seat=1)和 C(seat=3), **WHEN** A 被吞噬, **THEN** B 或 C 恰好一个同时被吞噬, 且即使被选中者也有 T-D2 也不递归

16. **GIVEN** 食客有 T-D3(BonusRatio=0.5), EffectiveBaseFee=20, **WHEN** 被吞噬, **THEN** 额外收入=floor(20×0.5)=10

17. **GIVEN** 食客有 T-D5(ExtraCardChance=0.3), **WHEN** 被吞噬且固定种子命中概率, **THEN** 产出 2 张同种族食材卡(1 张基础 + 1 张额外)

### 加菜类特性

18. **GIVEN** 食客有 T-A1(ResistCount=2), **WHEN** 前 2 次加菜, **THEN** 餐费=0, 卡牌耐久度不消耗, GoldSpentRatio 不更新, 情绪不变；**WHEN** 第 3 次加菜, **THEN** 正常生效

19. **GIVEN** 食客有 T-A2(TipRatio=0.1), DinerBaseFee=20, **WHEN** 被加菜 1 次, **THEN** 额外小费=floor(20×0.1)=2

20. **GIVEN** 食客 A 有 T-A3(GoldLossRatio=0.2), 其他食客 B 金币=100, **WHEN** A 被加菜 1 次, **THEN** B 金币变为 floor(100×0.8)=80

21. **GIVEN** 食客 A 有 T-A4(AttrReduction=2), 其他食客 B 的 Flavor=5, Freshness=5, **WHEN** A 被加菜 1 次, **THEN** B 的 Flavor=3, Freshness=3

### 环境类特性

22. **GIVEN** 食客 A 有 T-E2(AdjGoldBonus=0.2)坐在 index=3, 食客 B(index=2)金币=100, **WHEN** A 在场, **THEN** B 的有效金币=floor(100×1.2)=120；**WHEN** A 离场, **THEN** B 金币恢复为 100

23. **GIVEN** 食客 A 有 T-E2 坐在 index=0, **WHEN** 查询 aura 目标, **THEN** 只影响 index=1, 不影响 index=-1(不存在)

24. **GIVEN** 食客有 T-E1, 坐在任意座位(含 S5 基础餐费×2.0), **WHEN** 计算 EffectiveBaseFee, **THEN** 结果=0(后置覆盖乘法链)

### 边缘情况

25. **GIVEN** 食客有 T-D1(ResistCount=1)+T-D2, **WHEN** 吞噬判定命中但被 T-D1 抵御, **THEN** T-D2 不触发连坐

26. **GIVEN** 食客有 T-D3+T-D5, **WHEN** 霸王餐概率命中, **THEN** T-D3/T-D5 均不触发(霸王餐优先于吞噬特性)

27. **GIVEN** 食客有 T-A2(TipRatio=0.1)坐在 S4 板前座(EffectiveBaseFee=0), **WHEN** 被加菜, **THEN** 小费=0×0.1=0

28. **GIVEN** EffectiveDinerGold=10, EffectiveBaseFee=50, **WHEN** 食客落座, **THEN** GoldSpentRatio=50/10=5.0, 情绪查表返回高级别情绪(E4)

29. **GIVEN** 轮次中所有食客被吞噬/霸王餐, 全部座位 Empty, **WHEN** 检测, **THEN** 触发轮次提前结束

30. **GIVEN** 食客有 T-E1(基础餐费=0)+伪装型路径, **WHEN** 落座, **THEN** CumulativeSpent=0, 伪装型突变点需要更多加菜才能达到
